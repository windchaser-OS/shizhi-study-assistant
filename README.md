# 拾知 · 本地学习助手

围绕已有 Obsidian 仓库构建的个人学习工作台：编辑和检索笔记，整理错题，生成学习摘要、计划与复习卡片，并把照片中的学习内容转录为可审核的文字。

从源码运行时，默认笔记仓库位于 `obsidian/universities study program`。首次启动会自动创建空仓库，可以在浏览器和 Obsidian 中使用同一批 Markdown 文件。源码不携带示例笔记、个人笔记或学习记录。

## 下载安装版（Windows）

在 [GitHub Releases](https://github.com/windchaser-OS/shizhi-study-assistant/releases/latest) 下载 `shizhi-study-assistant-版本-windows-x64-setup.exe`，运行安装向导，然后从桌面或开始菜单打开「拾知 · 本地学习助手」。支持 Windows 10 / 11 的 64 位系统；安装包自带 Python、PDF 文本提取和公式资源，无需另装 Python、Node.js 或 Obsidian。

启动后会打开本机浏览器，同时显示拾知控制窗口。可以重新打开学习页面、选择已有的笔记文件夹、打开数据目录，或点击「退出拾知」关闭本地服务。关闭浏览器不会退出程序；关闭控制窗口会结束本次运行。AI 任务运行期间，退出和切换笔记库需要等待任务结束。AI 功能仍需在学习设置中配置自己的 API Key，或使用另行安装并登录的 Codex CLI。

安装版的默认笔记库位于 `%LOCALAPPDATA%\ShizhiStudyAssistant\vault`，数据库、AI 连接和运行设置位于 `%LOCALAPPDATA%\ShizhiStudyAssistant\data`。升级和卸载保留这些目录；备份时复制笔记库与整个数据目录。选择已有笔记库后，该文件夹也应单独备份。安装版不会自动导入源码目录内的个人笔记，已有使用者可以在控制窗口中选择原来的 Obsidian 笔记文件夹。

Release 也提供 `-portable.zip`：解压整个文件夹后运行 `ShizhiStudyAssistant.exe`。免安装版同样将个人数据保存到上述用户目录，移动或删除程序文件夹不会带走笔记。`SHA256SUMS.txt` 提供下载文件校验值，可以用 PowerShell 的 `Get-FileHash 文件路径 -Algorithm SHA256` 核对。

当前安装包未使用商业代码签名证书。Windows 可能提示“未知发布者”；请确认下载来源为本项目的 GitHub Release，并核对校验值。

## 获取源码

```powershell
git clone https://github.com/windchaser-OS/shizhi-study-assistant.git
cd shizhi-study-assistant
```

个人笔记库 `obsidian/`、运行数据 `.study-data/`、登录信息、环境配置和依赖缓存均不纳入 Git。使用自己的笔记库时，可以通过 `STUDY_VAULT` 指定其路径。

## 启动

需要 Windows 上的 Python 3.10 或更新版本。AI 功能可使用自己配置的 API Key；也可以选择已安装、已登录的 Codex CLI。

1. 双击项目根目录中的 `启动学习助手.cmd`，启动器会打开浏览器；也可以在根目录打开终端运行：

   ```powershell
   python -m study_app.server
   ```

2. 在浏览器打开 <http://127.0.0.1:8765>。
3. 在「学习设置 → AI 连接」配置并选择 AI 连接；使用 API Key 时无需安装或登录 Codex。
4. 点击「新建笔记」，上传学习资料或填写自己的内容；检查 AI 草稿和分类后保存。已有 Obsidian 笔记库可以通过 `STUDY_VAULT` 连接。

PDF 文本提取使用可选依赖 `pypdf`。需要使用 PDF 导入时，在项目根目录运行：

```powershell
python -m pip install -r requirements.txt
```

数学公式渲染所需的 KaTeX 资源随项目提供，日常启动不需要 Node.js 或 npm，也不依赖在线公式资源。如需重新构建前端依赖资源，先安装 Node.js，再依次运行 `npm ci` 和 `npm run vendor`。

启动服务的终端需要保持运行；在该终端按 `Ctrl+C` 可停止服务。若端口已被其他程序占用，请先关闭之前启动的学习助手。

## 配置 AI 连接

在「学习设置 → AI 连接」中可以保存多个连接配置，并切换当前使用的连接，适合在不同服务商、接口和模型之间切换。

1. 为连接填写名称，选择接口协议：OpenAI Chat Completions（`openai-chat`）、OpenAI Responses（`openai-responses`）或 Anthropic Messages（`anthropic`）。兼容服务需选择其实际支持的协议。
2. 填写服务商的 Base URL 和 API Key，点击「读取模型」。首次添加连接时也可以先读取列表，无需先填写模型或保存连接；读取时使用表单中当前的协议、地址和密钥。编辑已保存连接时，密钥留空可使用原有密钥。
3. 从读取的列表选择模型，或手动填写模型 ID。部分兼容服务不提供模型列表，仍可手动配置。
4. 保存连接，再将它设为当前连接并测试。测试会向该服务商发送一个简短请求，也可能产生 API 费用。摘要、对话、分类、图片转录和资料生成笔记均使用当前选定的连接。

照片转录和包含图片的笔记生成需要服务商与所选模型支持图片输入。读取模型列表或文本连接测试成功，不代表模型支持图片；请用实际图片检查效果。

API Key 保存在本机服务端的 `.study-data/ai-connections.json` 中，安装版位于 `%LOCALAPPDATA%\ShizhiStudyAssistant\data\ai-connections.json`；使用 `STUDY_DATA_DIR` 时保存在指定目录。此文件不纳入 Git，**密钥以明文保存，未加密**。保存后的密钥不会再次返回浏览器；编辑已有连接时留空可保留密钥，填写新密钥可替换。备份、复制或分享数据目录时会同时带上这些密钥。

如果选择 Codex 模式，请在终端确认 `codex --version` 能运行，并通过 `codex login` 完成 ChatGPT 账户登录。此模式使用 Codex CLI 的登录与用量额度，账户可用模型、权限和用量以 Codex 实际显示为准。本机已用 Codex CLI 0.159.0 验证；旧版 CLI 如不支持调用参数，请升级官方 CLI 后重试。Codex 模式不会自动使用环境里的 `OPENAI_API_KEY` 或 `CODEX_API_KEY`，API Key 连接需在应用中单独配置。

## 可以做什么

- **笔记管理**：浏览、编辑、保存本地 Markdown，导入 `.md`、`.txt` 或可提取文字的 PDF。
- **资料写笔记**：在「新建笔记」中上传课堂图片、PDF、Markdown 或 TXT，可以混合上传最多 6 份资料（合计 12 MB，每份文字文件最多 2 MB）。填写选填的整理要求，点击「根据资料生成笔记」，AI 会结合资料写出含来源说明的学习笔记草稿，并尝试拟定标题。草稿可以直接修改，确认后保存到 Obsidian。暂时关闭窗口会保留本次草稿和资料，重新点击「新建笔记」继续；刷新或关闭网页后未保存的草稿不会保留。也可以只填写正文，让 AI 整理已有内容。
- **笔记自动分类**：生成学习笔记时同时识别学科、笔记类型和最多 5 个标签，手写笔记默认在保存时分类。新笔记按「类型/学科」建议目录保存，例如 `02_错题本/数学/`；手动修改保存位置会保留你的选择。分类结果可以修改，取消「保存时自动分类」可直接保存而不请求分类 AI。打开已有笔记点击「自动分类」，检查后保存分类；编辑已有笔记时也可勾选保存时分类。已有文件保留原路径和双向链接。分类信息写入 Markdown 的 `category`、`subject`、`tags` 属性，在 Obsidian 和浏览器中都可使用；知识库提供类型和学科筛选。历史笔记未明确学科时显示「未分类」，不批量改写。
- **搜索与引用**：对中文和英文文本进行本地词法检索，查看命中的笔记，并在基于笔记的回答中追溯来源。检索依赖用词匹配；找不到时可更换关键词，或先补充笔记。
- **学习整理**：调用当前 AI 连接生成摘要、学习计划和复习卡片，先检查内容再采用。学习计划应由你提供考试时间、可用时间与具体目标。
- **间隔复习**：创建并复习卡片，依据自己的回答反馈安排后续复习。不要把浏览过答案算作已掌握。
- **照片整理**：上传照片，让支持图片输入的 AI 模型转录；核对公式、符号、题号后再保存为笔记。

PDF 导入提取已有文字层，不提供扫描 PDF 的 OCR。扫描页可以先转为图片，再走照片转录。这里使用轻量的本地词法搜索，未接入向量嵌入，也不依赖 LlamaIndex 或 AnythingLLM。

## 推荐的日常流程

1. 把课堂片段、临时问题或转录结果放到「00_收集箱」。
2. 整理为知识笔记或错题，保留教材/页码/题目来源。
3. 用自己的话写出结论、适用条件与一个反例；把关联笔记用 `[[双向链接]]` 连起来。
4. 从已核对的内容生成摘要或卡片。发现答案不可靠时，回到教材和原题校对。
5. 在浏览器完成到期卡片复习；每周根据错题和实际时间调整计划。

可以在自己的 Obsidian 仓库中创建空白模板。应用不会更改 Obsidian 的模板插件、日记插件或其他配置。

## 本地笔记目录

保存笔记时按分类自动创建所需目录；下列目录属于本地学习资料，不上传 GitHub：

```text
obsidian/universities study program/
├─ 00_收集箱/                     # 待核对和待整理内容
├─ 01_知识笔记/                   # 定义、定理、例题、联系
├─ 02_错题本/                     # 错误原因、正确思路、自测
├─ 03_学习计划/                   # 周计划和复盘
├─ 04_复习卡片/                   # 可读的卡片笔记与编写指引
├─ 05_学习档案/                   # 个人目标、偏好、工作流
└─ 90_模板/                       # 可自行创建的空白模板
```

项目从空知识库开始，所有笔记、卡片和学习记录由实际使用产生。使用自建模板时可标记 `category: template`，避免把模板计入实际错题统计。

## 数据、AI 与隐私

- Markdown 笔记保存在本地，复习等应用数据保存在本地 `.study-data` 目录中的 SQLite 数据库。备份时同时保存笔记仓库和 `.study-data`。学习助手只绑定本机地址 `127.0.0.1`，设计用于个人电脑上的本地使用；不要将此端口直接暴露到公网。
- **点击 AI 功能时，所选文本、用于检索的相关笔记片段或上传的照片会发送到当前选定的 AI 服务商在线处理。** “本地笔记”不等于“离线模型”。仅提交你愿意发送的材料；API 连接会将密钥发送到配置的 Base URL 所指向的服务商进行认证。
- API Key 模式可能按服务商规则产生费用，费用与额度由该服务商管理；Codex 模式消耗对应账户的可用额度。
- 应用不会自动继承你在 ChatGPT 网页里其他对话的历史或记忆。希望模型知道的课程背景、目标和约束，应在当前请求或相关档案中明确提供。
- API 模式只请求模型的文本或图片理解输出；Codex 模式使用只读执行约束。模型输出回到应用后由你审核、保存，笔记写入由本地服务完成。
- Obsidian 自身的同步行为由你的 Obsidian 设置控制；本项目没有更改那些设置。请在重要修改前备份仓库。

AI 可能误读照片、遗漏适用条件或给出错误推导。引用表示答案使用了哪些本地材料，并不等同于已通过事实核验；公式和答案仍需对照原始材料检查。

## 常见问题

**页面打不开**：安装版需保持拾知控制窗口运行，点击「打开学习空间」，或使用窗口中显示的实际地址；默认端口被占用时会自动换用空闲端口。源码版需确认启动终端没有退出，默认地址是 `http://127.0.0.1:8765`，不是 `https://`。

**API 连接测试失败**：检查接口协议、Base URL、API Key、模型 ID 和服务商额度。模型列表读取失败时可以手动填写模型 ID；兼容接口可能只支持其中一种协议。

**Codex 模式提示找不到 Codex**：安装或修复 Codex CLI 后，重新打开终端，让新的 `PATH` 生效；先单独确认 `codex --version` 可以运行。也可改用 API Key 连接。

**AI 提示认证失败、额度不足或网络错误**：API 模式请检查当前服务商的密钥、额度和网络；Codex 模式请在终端检查 Codex 的实际状态，必要时执行 `codex login`。本地浏览、编辑和搜索笔记不依赖模型成功响应。

**搜索没找到内容**：尝试笔记中实际出现的词，例如「可导」「连续」「绝对值」。当前检索不保证理解所有同义表述。

**照片中的公式不准确**：提高图片清晰度，减少一张图中的内容量，并在保存前人工校对分数线、指数、上下标、正负号和边界条件。

**Obsidian 与浏览器都在编辑同一篇笔记**：先在一个界面保存，再在另一界面重新打开。尽量避免两边同时保存同一文件。

## 开发与配置

`python -m unittest discover -s tests -v` 运行本地测试；测试使用临时仓库和模拟的 AI 返回，不消耗模型额度或产生 API 费用。`node --check web/app.js` 检查前端脚本语法。实际模型联网调用单独验证，不是自动测试的一部分。

### 构建与发布 Windows 软件

构建使用固定的 Python 3.12.10 x64、Inno Setup 6.7.3，以及 Node.js（前端语法检查）。在安装这两个指定版本的构建工具后，运行：

```powershell
py -3.12 -m venv .venv-build
.\.venv-build\Scripts\python.exe -m pip install -r requirements-build.txt
.\scripts\build-windows.ps1 -PythonExe .\.venv-build\Scripts\python.exe
```

若 Inno Setup 不在默认位置，增加 `-IsccPath "编译器绝对路径\ISCC.exe"`。产物位于 `dist/release/`。脚本运行单元测试、前端语法检查、冻结程序自检和资源检查；`scripts/test-windows-install.ps1 -InstallerPath "安装包路径"` 可在项目的临时目录中验证安装、同版本覆盖安装和卸载。GitHub Actions 同样执行这些检查。

第三方许可说明随软件分发，见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。构建仅收集程序代码和明确指定的资源，不包含个人笔记、API Key、数据库或开发环境。

GitHub Actions 的 Windows 发布流程会检查版本、运行测试、构建并验证软件，然后上传产物。更新 `package.json` 的版本后推送匹配的 `v版本` 标签即可发布新版本；也可手动运行工作流构建供检查的产物。具体构建参数见脚本帮助 `Get-Help ./scripts/build-windows.ps1 -Detailed`。

可选环境变量：`STUDY_VAULT` 指定 Obsidian 仓库，`STUDY_DATA_DIR` 指定本地应用数据目录（数据库及 AI 连接配置），`STUDY_CODEX_PATH` 指定 Codex 可执行文件，`STUDY_CODEX_MODEL` 选择 Codex 模式下账户可用的模型。未设置时使用默认本地目录和 CLI 默认模型。API 连接和模型在「学习设置 → AI 连接」配置。自定义端口使用 `python -m study_app.server --port 8767`。

一次仅执行一个 AI 请求，单次超时为 180 秒；Codex 模式超时后会结束子进程。长篇整理每次处理前 32000 字符，并在结果中提示处理范围；新建笔记的多份文字资料共享 32000 字符，另参考已有草稿的前 16000 字符。长资料应按章节拆分。上传资料的原文件不会附加保存到 Obsidian，生成的笔记会保留来源文件名；请自行保管原始资料。
